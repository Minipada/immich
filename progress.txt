Issue #6: Per-window language detection with sticky resolution

Language is detected continuously instead of once per video, each stored
segment carries its resolved language, and an administrator can force a
single language across the library. All eight acceptance criteria are
covered, including the end-to-end one — a real two-switch video was built
and transcribed (results below).

ML side (immich_ml/models/transcription/whisper.py):
- `multilingual` was already on from the tracer bullet, so faster-whisper
  re-decides the language at every 30s encoder window. It does not expose
  that decision, and `Segment` has no language field in 1.2.1, so detection
  is repeated through the public `detect_language` API and each segment is
  labelled by the window its midpoint falls in.
- Repeating it costs one extra encoder pass per window. Windows are
  therefore detected lazily and shared between every segment in them, so a
  window with ten segments is detected once and a window with none — music,
  silence, anything VAD dropped — is never detected at all.
- The midpoint, not the start, picks the window, so a segment straddling a
  boundary is labelled by the window it mostly belongs to. The index is
  clamped to the last window that exists, because a model can report past
  the end of the audio it was given.
- Confidence is passed through raw. Deciding whether to believe a switch is
  the server's job, so the adapter stays a thin reporter.
- A configured override is passed as `language=` and turns `multilingual`
  off, so the model does not detect at all. Overridden segments report
  confidence 1.0, which makes the server's stickiness rule a no-op rather
  than a special case. `configure()` applies a changed override to an
  already-cached model, which is the only way options reach one.

Stickiness (server/src/utils/transcription.ts, `resolveSegmentLanguages`):
- Believe a detection at or above `minLanguageConfidence`; below it the
  segment keeps the language established so far.
- Because an unsure segment resolves to the established language rather than
  to its own detection, the established language moves only on a confident
  detection. That is what makes a run of unsure segments unable to drift:
  the invariant is structural, not a length limit. It also makes the last
  resolved language the established one, which is what the caller carries
  into the next chunk.
- At the threshold exactly the detection is believed. The setting reads as
  the confidence required, so requiring strictly more would be off by one
  detection's worth of hesitation.
- The first segment of the first chunk is the only one with nothing to
  inherit and keeps its own detection whatever the confidence — a guess
  beats no language, and the first confident detection after it takes over.

Carrying it across boundaries (transcription.service.ts, transcript.repository.ts):
- The established language is threaded from chunk to chunk in memory, and
  read back from the last written segment (`getLastLanguage`, ordered by
  start time, not insertion order) when a run resumes. Without the read-back
  the first segment after a restart would look like a first segment and
  could re-anchor the transcript on a misdetection.
- A chunk with no speech leaves the established language untouched rather
  than clearing it, so music between two people talking does not reset it.

Schema and config:
- `transcript_segment.language`, nullable text (migration 1785426524830).
  Nullable only because segments written before this change have none.
  Per-segment rather than per-asset: WebVTT scopes language at track level
  so it cannot be declared per cue, and a mixed transcript renders fine in
  one track, but storing it per segment makes per-language tracks a
  rendering change later rather than a schema change.
- `machineLearning.transcription.language` (null = detect; validated as a
  2-3 letter code, which covers every Whisper code including `yue`) and
  `minLanguageConfidence` (0.7, range 0..1). OpenAPI spec and the TypeScript
  SDK client regenerated; SQL query snapshots regenerated.
- No administrator UI: issue #13 covers transcription settings, and the
  earlier chunking settings were added the same way.

End-to-end verification (the acceptance criterion that needed real audio):
- Built a 135s video from two public-domain LibriVox recordings — 45s
  English, 45s French, 45s English — so there are two switches with known
  ground truth, then ran the production path: the server's exact ffmpeg
  extraction flags, the same chunk plan, the real `WhisperTranscriber`, and
  the real `resolveSegmentLanguages` over its output.
- The text is correct in both languages across both switches. French is
  transcribed as French, English as English, with no phonetic transliteration
  anywhere.
- Detected boundaries at the 0.7 default: en 0-29.5s, fr 29.5-90.0s, en
  90.1-135.0s, against a truth of 0-45 / 45-90 / 90-135.
- The 15.5s error on the first boundary is window granularity, not
  stickiness. The window spanning 29.5-58.7s contains both languages and
  reads as French at 0.790 — every single-language window scored 0.985 to
  1.000, so the confidence drop lands exactly where the ambiguity is. At a
  0.8 threshold that window is disbelieved and the same boundary lands
  13.6s late in the other direction; no threshold fixes it, because the
  window genuinely is half of each. The second boundary, which falls on a
  chunk edge, is exact.
- That spread also brackets the default usefully: 0.7 is low enough to
  accept a genuine switch (French windows scored 0.985) and high enough to
  reject the ambiguous one at 0.790. Raised to 0.99 the resolver never
  believes the switch at all and holds English for the whole video, which is
  what an over-strict threshold buys.
- Override checked on the same audio: forcing `en` over the French section
  yields English text ("without other shelter than the vote of the gods"
  for "sans autres abris que la voûte des cieux"), confirming detection is
  genuinely off rather than merely overruled, and that `configure()` applies
  to a loaded model.

Tests:
- 9 unit tests on the resolver: confident switch, low-confidence
  inheritance, first segment, sustained low confidence, confidence exactly
  at threshold, an established language carried in, a confident detection
  overriding it, an empty chunk, and a return to an earlier language.
- 5 service tests: resolved language stored per segment, established
  language carried across a chunk boundary, inherited from an interrupted
  run on resume, override passed to the model, and null passed when
  detection is automatic.
- 7 new ML tests: per-window detection, one detection per window shared
  between segments, midpoint attribution for a straddling segment, clamping
  for a segment overrunning the audio, the override path, and `configure`.
- 4 new medium tests on `getLastLanguage`: no segments, latest by start time
  rather than insertion order, a pre-detection segment, and isolation
  between assets.
- Full server unit suite green (2302 passed, 2 skipped). ML suite green (114
  passed, 3 skipped). Server lint/format/typecheck, web svelte-check, and ML
  ruff/mypy --strict all green.

Also fixed: `mypy --strict` was already failing on whisper.py before this
branch touched it (a stale `type: ignore[return-value]` on `_load`). It is

rather than left broken.

Not done / caveats:
- Detection granularity is one 30s encoder window, which is the finest the
  model has an opinion at. A switch mid-window is attributed to whichever
  language the window as a whole reads as, as measured above. Narrowing it
  would mean overlapping windows and more encoder passes; worth revisiting
  only if mid-window switching turns out to matter in practice.
- The medium-test harness still cannot start its own database here:
  testcontainers fails against this host's Docker with "Log stream ended",
  on a clean checkout as much as on this branch. The medium tests were run
  against the running `ghcr.io/immich-app/postgres` with a local global
  setup pointed at it; all 13 in the transcript suite pass.
- The Dart SDK was not regenerated: `openapi-generator-cli` is unavailable
  here, and `mobile/openapi` already lacked `TranscriptionConfig`, so this
  branch does not make it any staler.
- `minLanguageConfidence` is exposed but the silence thresholds and the
  window size remain constants, as before.
