Issue #3: Tracer: end-to-end subtitles on a short video

Implemented the thinnest complete path for automatic video subtitle
generation, end to end: upload a short video with speech -> a transcript
job runs automatically -> captions render in the web player.

Machine-learning service (machine-learning/):
- Added `ModelTask.TRANSCRIPTION` and `ModelSource.WHISPER`.
- Added `WhisperTranscriber` model adapter (models/transcription/whisper.py)
  wrapping faster-whisper. Overrides the four base-class assumptions that
  don't apply to it: `_download` (pulls from the `Systran/faster-whisper-*`
  HF namespace instead of `immich-app/*`), `_load` (constructs a
  `WhisperModel` instead of an onnx/armnn/rknn session, with an explicit
  `cpu_threads` cap), `model_path`/`cached` (the model is a directory with
  a `model.bin` marker file, not a single suffixed file), and forces
  `ModelFormat.ONNX` so the base class's hardware-format autodetection is
  a no-op for this model type.
- VAD (`vad_filter=True`) and continuous language detection
  (`multilingual=True`) are enabled unconditionally.
- Added an `audio` payload type to the `/predict` endpoint alongside the
  existing `image`/`text` types.
- Added `faster-whisper` dependency; `uv.lock` regenerated.
- Tests: machine-learning/test_main.py::TestTranscription (8 tests) cover
  directory-based cached/model_path, the whisper HF download namespace,
  the CPU thread cap being passed to WhisperModel (default and override),
  and VAD/multilingual being enabled on predict.

Server (server/):
- New `transcript_segment` table (assetId FK, cascade delete on asset
  removal, startTime/endTime/text) via migration
  1785274558937-AddTranscriptSegmentTable.ts. Added `asset_job_status
  .transcribedAt` for job-completion tracking, mirroring `ocrAt`.
- New `QueueName.Transcription` / `JobName.AssetTranscribe(QueueAll)`,
  wired into JobRepository, QueueService (start/concurrency/legacy
  status), and job.service.ts's post-thumbnail fan-out: transcription is
  queued only in the existing `asset.type === AssetType.Video` branch,
  alongside AssetEncodeVideo.
- New `TranscriptionService` (services/transcription.service.ts):
  extracts audio from the ORIGINAL file (never transcoded) as 16kHz mono
  PCM WAV via a new `MediaRepository.extractAudio`, calls the ML
  `/predict` endpoint via a new `MachineLearningRepository.transcribe`,
  persists segments, and cleans up the temp file. Skips cleanly (does not
  fail the job) when transcription is disabled by config or the video has
  no audio stream, per acceptance criteria.
- Config: `TranscriptionConfigSchema` (enabled, modelName, threads) under
  `machineLearning.transcription`; default model `small`, thread cap 4.
  The thread cap is always sent to the ML service, never left at "0 =
  unbounded".
- New `GET /assets/:id/captions.vtt` endpoint (asset.controller.ts)
  rendering WebVTT on demand from stored segments; returns valid (possibly
  empty) WebVTT for any video so the player's `<track>` never 404s.
- Tests: transcription.service.spec.ts (9 tests) cover the disabled path,
  the no-audio-track path, the hidden-asset path, and the success path.
  Updated job.service.spec.ts / queue.service.spec.ts for the new queue.

Web (web/):
- Added `<track kind="subtitles">` to both the HLS and plain `<video>`
  branches in VideoNativeViewer.svelte, pointed at the new captions.vtt
  endpoint via a new `getAssetCaptionsUrl` helper. Per the issue #2 spike
  findings, browser auto-selection of `<track default>` isn't reliable on
  the custom `hls-video` element, so `track.mode = 'showing'` is set
  explicitly in the existing `handleCanPlay` hook.
- Added the Transcription queue to the admin Jobs settings page.

Regenerated the OpenAPI spec and TypeScript SDK (`@immich/sdk`) for the
new endpoint/DTOs.

Verification: full test suites pass in all three projects (server: 2259
passed, web: 518 passed, machine-learning: 106 passed), plus `tsc
--noEmit`, `svelte-check`, mypy, and eslint/ruff on all touched files.

Not done (explicitly out of scope for this tracer bullet, per the issue):
audio is extracted from the whole file in one piece with no chunking; no
transcript panel/search/inline editing UI (later PRD slices); no captions
in the Chromecast remote viewer or the Memories video viewer.
